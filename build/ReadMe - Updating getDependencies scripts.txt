getDependencies-windows.sh downloads the binary dependencies that are not in this repo
(ghostscript, ffmpeg, GraphicsMagick, lame, PodcastUtilities, XliffForHtml, Bloom.chm...)
from our TeamCity server at https://build.palaso.org. ./init.sh runs it for you.

It used to be generated by buildupdate.rb (https://github.com/chrisvire/BuildUpdate) from
the TeamCity build configuration. We no longer do that: the generator is obsolete, and the
script is short enough to maintain directly. EDIT IT BY HAND. Do not run buildupdate.rb
against it -- that would throw away the download error handling and the copying-from-
another-worktree shortcut.

To add or change a dependency:

1. Find the artifact on build.palaso.org, and note the build configuration id (e.g. bt396)
   and the artifact's file name.

2. Add a copy_auto line near the other ones, of the form

     copy_auto https://build.palaso.org/guestAuth/repository/download/<buildId>/latest.lastSuccessful/<artifact> <destination>

   The destination is relative to this build directory, so it starts with "../"; make sure
   there is a "mkdir -p" line for its directory.

3. If the artifact is a zip that has to be unpacked, download it to ../Downloads and add an
   extract_zip line at the bottom saying where to unpack it.

4. Update the "*** Results ***" comment block. It is only documentation now -- a record of
   which TeamCity builds these artifacts come from -- but it is worth keeping accurate.

There is no getDependencies-Linux.sh in the repo any more, although debian/rules line 24
still invokes one -- so Linux packaging by that route is already broken, independently of
this script. Earlier versions of this file described how to regenerate both.
